# FORMA

Сайт на HTML, CSS и JavaScript: главная, три сервиса и три legal-страницы. Дизайн сохранён. Форма находится только на главной странице.

## Единое управление

Единственный файл настроек и контента — `config/config.js` в готовом архиве, `dist/config/config.js` в репозитории.

Сохраняйте формат `window.SITE_CONFIG = { ... };`: внутри объекта используются JSON-значения, двойные кавычки, без функций, комментариев и запятой после последнего поля. Этот же файл безопасно читает PHP через JSON-декодирование, без выполнения JavaScript.

- `brand`, `company`, `email`, `address`, `logo`, `favicon`: общие реквизиты и изображения бренда.
- `nav`: ссылки меню. Можно менять подписи и добавлять пункты.
- `services`: названия, описания, преимущества, заголовки и ссылки трёх сервисов. `slug` соответствует существующему имени страницы; создание нового маршрута требует отдельного HTML-файла и шаблона.
- `pageTitles`: названия страниц для вкладки браузера и общих legal-заголовков.
- `shared`: подписи и ссылки хедера, футера и cookie-плашки.
- `pages`: весь контент страниц. В каждой странице `sections` — секции в порядке отображения, с их HTML-id. Внутри `content` поля `heading`, `paragraph`, `text`, `link`, `image`, `imageAlt`, `hoverImage`, `animatedHeading` содержат соответствующий текст, ссылку, путь к изображению, описание или текст анимированного заголовка. Числа в названиях различают элементы одной секции. Значения можно менять; имена ключей нужно сохранять. Секции можно переставлять или удалять в массиве.
- `ui`, `search`: интерфейс, поиск и адреса демонстрационных вкладок.
- `form`: обработчик, включение отправки, тема письма и все сообщения формы.

Маркеры вида `@@brand@@` или `@@services.0.name@@` подставляют общие значения. Они позволяют изменить бренд или название сервиса один раз. Повторяющиеся элементы слайдера используют общие поля внутри секции.

`assets/templates.json` хранит только разметку и маркеры. Для изменения контента его редактировать не нужно. `assets/app.js` отвечает за отображение, меню, табы, формы, аккордеоны, слайдеры и анимации.

Изображения указываются путями относительно корня сайта. Заменяйте файл или путь `image...` в нужной секции, а также его `imageAlt...`. Для изображений общей галереи меняйте `hoverImage...`.

Запускайте сайт через HTTP/HTTPS, а не открытием HTML через file://: разметка загружается из assets/templates.json.

## Отправка формы

Загрузите содержимое ZIP в корень сайта на PHP 8.1+ хостинге. `contact.php` должен лежать рядом с `index.html`, а `config/config.js` — в подпапке `config`.

В `config/config.js` замените `email` на реальный корпоративный адрес получателя. Этот же адрес используется в From; его домен должен быть разрешён почтовой системой хостинга. `form.enabled` уже установлен в true. `form.endpoint` по умолчанию равен `contact.php`. Пароли в публичном config.js хранить нельзя.

Настройте исходящую почту хостинга для PHP mail(). Reply-To содержит адрес посетителя. Обработчик проверяет обязательные поля, email, согласие, ловушку для ботов и размер запроса; повторная отправка с одного IP ограничена одной попыткой в минуту. Все ответы имеют JSON-формат.

Сообщение об успехе появляется только после принятия письма почтовой системой. Это не подтверждает доставку во входящие: после настройки проверьте реальное письмо, спам, SPF/DKIM и журнал почты.

Адрес hello@forma-studio.example — заглушка, отправка с ним блокируется. Публикация Sites статическая и PHP не выполняет. Рабочая отправка требует PHP-хостинга и реального email.

## Проверки

Проверены синтаксис JavaScript, сборка семи страниц, наличие изображений, подстановка общих настроек и отсутствие комментариев в коде. PHP-runtime в среде разработки недоступен; выполнение PHP и реальная доставка почты должны быть проверены на целевом хостинге.

## Лицензии

Лицензионные уведомления библиотек сохранены отдельно в THIRD-PARTY-NOTICES.txt. Источники фотографий — assets/v3-photos/credits.json и assets/v4-photos/credits.json. Юридические тексты описывают реализацию сайта; перед запуском заполните реальные реквизиты и сведения об обработке данных.
